# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Stack

Symfony 7.4 + API Platform 4.3 starter on PHP 8.5, Doctrine ORM 3, PostgreSQL 16, Lexik JWT, Nelmio CORS, PHPUnit 13. Runs under Docker (PHP-FPM + Nginx 1.25 + Postgres 16 + Mailpit).

## Working in the containers

**Never use the host PHP/composer/symfony binaries** — everything runs inside the `php` container. All common operations go through the `Makefile`, which wraps `docker compose exec php …` with the host user/group so file ownership stays correct.

Key targets:

| Target | Purpose |
|---|---|
| `make install` | Full bootstrap: build images → `up -d` → `composer install` → generate JWT keys → run migrations |
| `make start` / `make stop` / `make restart` | Lifecycle |
| `make shell` | Bash inside the PHP container (use this to inspect vendor/, run ad-hoc commands) |
| `make migrate` / `make migrate-diff` | Doctrine migrations |
| `make reset` | Drop DB → create → migrate → fixtures |
| `make jwt` | Regenerate the Lexik keypair into `config/jwt/` |
| `make test` | PHPUnit (`--testdox`) |
| `make qa` | `lint` + `cs` + `analyse` + `test` |
| `make composer c="require foo/bar"` | Proxy to composer |
| `make console c="debug:router"` | Proxy to `bin/console` |

Running a single test (inside the container, via `make shell` or `make console`):

```bash
php bin/phpunit --filter TestClassName::testMethod
php bin/phpunit tests/Path/To/SomeTest.php
```

Note: `make cs` / `make cs-fix` call `vendor/bin/php-cs-fixer` and `make analyse` calls `vendor/bin/phpstan`, but **neither tool is currently in `composer.json`**. Add them (as dev deps) before expecting those targets to work.

## Architecture

This is a skeleton — `src/ApiResource`, `src/Controller`, `src/Entity`, `src/Repository`, `migrations/` are empty. The scaffolding that *does* exist shapes how new code should plug in:

- **API routing**: `config/routes/api_platform.yaml` mounts API Platform at the `/api` prefix. Any `#[ApiResource]`-annotated class (typically under `src/ApiResource` for DTO-style resources or `src/Entity` for Doctrine-backed ones) auto-exposes CRUD under `/api`.
- **API defaults** (`config/packages/api_platform.yaml`): `stateless: true`, and `Vary: Content-Type, Authorization, Origin`. Keep resources stateless.
- **Security** (`config/packages/security.yaml`): currently only a `users_in_memory` provider and a lazy `main` firewall with no access rules wired. JWT is installed (Lexik) but **not yet attached to the firewall** — to enable API auth you need to add `json_login` + `jwt` to the `main` firewall and add an `access_control` entry for `^/api`. Keys live under `config/jwt/` and are generated by `make jwt`.
- **CORS** (`config/packages/nelmio_cors.yaml` + `CORS_ALLOW_ORIGIN` env): regex-based allow-list, defaults to localhost.
- **Test environment**: `phpunit.dist.xml` sets `failOnDeprecation/Notice/Warning=true` — deprecations break the suite. The `App\Tests\` PSR-4 root is `tests/`. `when@test` in `security.yaml` lowers password hasher costs.
- **Dockerfile** has two stages: `dev` (adds Xdebug, used by `docker-compose.yml`) and `prod` (copies code, `composer install --no-dev`). `docker-compose.yml` only builds the `dev` target.
- **Env files**: `.env` (committed defaults, overridden by `.env.local`), `.env.dev`, `.env.test`. `DATABASE_URL` points to the `database` service hostname — only valid from *inside* the Docker network.

## Conventions from the repo

- README and Makefile comments are in French — match that tone if editing them.
- The `make install` bootstrap order (build → up → composer → jwt → migrate) is load-bearing: JWT keys must exist before the app boots in any meaningful way, and migrations need the DB healthcheck to pass (handled by `depends_on.condition: service_healthy`).
